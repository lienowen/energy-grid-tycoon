# Energy Grid Tycoon

上帝视角城市能源建设经营游戏。玩家直接操作未来城市沙盘，选择能源项目、挑选用地、完成施工，并观察供电、街区灯光、资金、满意度和环境随决定发生变化。

## 当前主线：City-01 商业垂直切片

`main` 当前只服务 City-01 的商业垂直切片，不再同时扩展多座城市和外围系统。

当前版本保留模拟、电力、经济、事件、存档、PixiJS 世界、镜头与输入等技术底座，但**未达到市场发布标准**。在 City-01 的真实试玩、生产素材和商店截图全部通过前，冻结：

- 新城市；
- 新的外围成长或元系统；
- 与第一轮体验无关的新资源类型；
- 只增加数据、标签或面板，却不改变城市世界的功能。

具体发布门见 `docs/COMMERCIAL_VERTICAL_SLICE.md`，机器可读状态见 `product-scope.json`。

## 核心玩家循环

```text
观察城市问题
→ 选择建设项目
→ 沙盘高亮可用地块
→ 点击地块让设施分阶段建成
→ 设施接入并改变城市供电与街区表现
→ 获得资金、满意度或环境结果
→ 扩建、关闭或调整发展方向
```

主画面必须始终是可操作的城市世界，而不是数据后台。HUD 只解释结果，不能代替结果。

## 当前已验证的工程能力

- 持续存在的 Canvas / PixiJS 城市沙盘，不随模拟 tick 重建；
- 鼠标拖动、滚轮缩放、双击归位和移动端双指缩放；
- 3/4 俯视投影、道路网络、动态车流、窗灯和环境反馈；
- 分区级供电、停电、储能、收入、人口、满意度和环境模拟；
- 七类独立能源设施模型与设施运行反馈；
- 地基、脚手架、主体升起和接通线路的分阶段施工状态；
- 玩家选择项目、选择用地、确认建设和保存施工进度；
- 设施位置、运行状态、等级、储电量与施工状态进入版本化存档；
- 点击已建设施查看、关闭或扩建；
- 固定种子的城市事件、视觉与规则组合；
- 自动保存、损坏存档恢复、重试和响应式 HUD；
- 全局素材目录、按城市加载、失败降级和自动内容校验。

这些能力只代表技术底座可继续使用，不代表产品已经完成。

## City-01 发布目标

陌生玩家进入后，应在五分钟内完成并理解：

1. 看见一个明确的城市能源问题；
2. 选择一个可识别的能源设施；
3. 在城市中选择真实用地；
4. 看见施工、接入和城市变化；
5. 理解本次建设对供电、资金、满意度或环境的影响；
6. 产生下一次扩建或调整的明确动机。

不看文字标签也应能辨认主要城区、光伏、风电、燃气、储能和变电站。城市应占有效画面至少 70%，桌面与移动端截图均需达到商店展示质量。

## 开发

```bash
npm install
npm run dev
```

提交前运行完整质量门：

```bash
npm run quality
```

也可以单独运行：

```bash
npm run check:product  # 主分支产品方向与发布声明校验
npm run check:content  # 地块、配置、素材引用、重复文件、尺寸和体积预算
npm test               # 视觉种子、模型、投影、落位、存档和规则测试
npm run build          # 严格类型检查和生产构建
```

CI 会按相同顺序执行产品方向、内容、测试和生产构建检查。工程检查通过不等于市场发布通过，详细标准见 `docs/QUALITY_GATE.md`。

## 内容生产规则

City-01 发布门通过之前，不开始第二座城市。当前内容工作只允许围绕：

```text
City-01 地图构图
+ 正式城区与能源设施素材
+ 施工、停电和复电的世界反馈
+ 前五分钟任务闭环
+ 桌面与移动端商店截图
```

设施允许建设的区域来自设施配置；地块坐标、用途、高度、初始位置和镜头参数来自城市配置。业务代码不按城市编号复制分支。

## 架构

- `core`：应用、会话、状态、地图配置、版本化存档、领域事件与城市进度；
- `systems`：地图落位、电力、储能、经济、事件、目标、城市发展、方向、引导和统计；
- `rules`：Condition、Action、Modifier 与 Behavior 的组合协议和注册表；
- `gameplay`：少量必须通过代码实现的独特行为；
- `buildings`：设施模型、位置、工厂、集合和运行时快照；
- `data`：城市地图、地块、设施、事件、发展项目和方向参数；
- `resources`：全局素材目录、元数据、预加载和城市素材规划；
- `presentation`：把游戏状态映射成只读城市状态；
- `ui/world`：Canvas / PixiJS 镜头、输入、设施、街区、道路、车辆和命中检测；
- `ui`：顶部 HUD、目标、提示、建造栏和二级工具。

完整架构规则见 `docs/ARCHITECTURE.md`。

核心原则：

- 世界先于面板；
- 玩家行动先于数据展示；
- Canvas / PixiJS 负责城市世界，DOM 只负责 HUD；
- 稳定能力做引擎，重复变化做配置；
- 素材使用全局资源 ID，不在业务代码中写路径；
- 存档保存状态和运行时快照，不复制配置；
- 视觉随机使用稳定种子，可复现、可测试；
- 自动测试证明工程可运行，真实截图和试玩证明游戏可发布。
