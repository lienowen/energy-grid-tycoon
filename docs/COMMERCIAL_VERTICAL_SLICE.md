# City-01 商业垂直切片

## 决策

`main` 当前只服务一个目标：把 City-01 做成能够真实试玩、能够形成商店截图、能够验证玩家兴趣的商业垂直切片。

在本文件的发布门全部通过前，冻结以下工作：

- 新城市；
- 新的外围成长或元系统；
- 与 City-01 首轮体验无关的新资源类型；
- 只增加数据、面板或标签，却不改变城市世界的功能；
- 无法直接进入运行时的展示板、拼图或候选素材替换。

模拟核心、存档、规则系统、PixiJS 世界、镜头与输入继续保留。现阶段不推倒技术底座，但也不再以工程完整度代替游戏完成度。

## 玩家体验目标

陌生玩家进入游戏后，应在五分钟内完成并理解下面的闭环：

```text
观察城市问题
→ 选择一个能源设施
→ 在城市中选择用地
→ 看到真实施工过程
→ 设施接入后城市供电与街区表现发生变化
→ 收到收入、满意度或环境结果
→ 产生下一次扩建或调整的明确动机
```

任何关键结果都必须优先发生在城市世界中。HUD 只解释结果，不能代替结果。

## 发布门

只有以下项目全部由真实运行截图或浏览器操作证据确认后，才允许把 `product-scope.json` 中的 `storeReady` 改为 `true`。

1. **前五分钟可玩**
   - 无需阅读长文档即可进入 City-01；
   - 玩家能完成选择、落位、施工和接通；
   - 不存在无法继续、按钮失效或流程断裂。
2. **城市可读**
   - 不看文字标签也能区分主要城区；
   - 光伏、风电、燃气、储能和变电站可被直接识别；
   - 城市占有效画面至少 70%，核心区域不被 HUD 遮挡。
3. **世界反馈真实**
   - 施工不是进度条替代，城市中可见地基、主体和接通过程；
   - 停电、转供和复电通过窗灯、街灯、线路或活动变化体现；
   - 建设和运行结果真实影响供电、资金、满意度或环境。
4. **生产素材通过**
   - 正式运行素材具有透明边、统一锚点、统一占地和一致视角；
   - 候选素材不得进入运行资源目录；
   - 不允许以缩放、遮罩或拼贴掩盖素材质量问题。
5. **商店截图通过**
   - 桌面和移动端各至少一张运行截图达到商店展示质量；
   - 截图本身能够表达城市、能源设施和玩家行动；
   - 不使用调试标签、开发说明或大面积信息面板支撑理解。

## 完成定义

CI、类型检查、单元测试和构建成功，只证明工程没有明显损坏。

商业垂直切片完成必须同时满足：

- 自动质量门通过；
- 发布门全部通过；
- 真实试玩流程通过；
- 正式运行截图通过；
- `product-scope.json` 的所有 acceptance 字段均为 `true`。

第二座城市只能在 City-01 发布门全部通过后开始。
